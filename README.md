# TelegramBot — самостоятельный OpenAI-помощник клиники

Это отдельный Python-проект. Он не импортирует код сайта, не требует FastAPI,
не использует базу сайта и запускается отдельным процессом. Сайт содержит только
ссылку на `https://t.me/surgerymgu_bot`.

## Что работает

1. Бот представляется виртуальным помощником и получает согласие.
2. Спрашивает имя, причину обращения, длительность и телефон.
3. OpenAI отвечает на описание обращения по `instructions.txt`.
4. Показывает полную заявку и ждёт кнопку «Отправить заявку».
5. Сохраняет её в SQLite и отправляет во все обнаруженные группы и каналы, где бот администратор.
   Пациент видит данные заявки и кнопку подтверждения; названия чатов не отображаются.
6. Подтверждает передачу только после успешного ответа Telegram.

Получение полей и отправка управляются кодом. Модель не имеет инструментов
отправки, не выбирает адресата и не может изменить группу через сообщение пациента.
Не ставит диагноз и не назначает лечение. Без OpenAI-ключа анкета работает с
фиксированными ответами; `/operator` отключает OpenAI для текущего обращения.
После согласия команда `/ask ваш вопрос` позволяет задать помощнику дополнительный вопрос, не сбрасывая анкету.

## Локальный запуск (macOS / Linux, Python 3.12+)

Из этой папки:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
cp -n .env.example .env
chmod 600 .env
nano .env
.venv/bin/python bot.py
```

В `.env` заполнить:

- `TELEGRAM_BOT_TOKEN` — токен BotFather.
- `TELEGRAM_GROUP_ID` — **необязательный** ID одного уже существующего чата для обнаружения при запуске. Можно оставить пустым.
- `TELEGRAM_TOPIC_ID` — необязательная тема только в чате `TELEGRAM_GROUP_ID`. В остальных чатах заявки отправляются в общий чат.
- `OPENAI_API_KEY` — API-ключ OpenAI, не токен входа в ChatGPT.
- `OPENAI_MODEL` — модель Responses API, доступная вашему API-проекту. В примере `gpt-5-mini`.

Токены не вставляются в исходный код и не попадают в Git. `.env` не отправлять в чат.
Инструкции редактируются в `instructions.txt`; после изменения перезапустить бота.
Бот ведёт анкету и отвечает через OpenAI только в личных чатах. В группах и каналах он отправляет заявки; переписка участников не передаётся OpenAI.

## Все чаты, где бот администратор

Добавьте бота администратором в нужные группы или каналы. Запущенный бот получает
событие `my_chat_member`, проверяет права через Telegram и запоминает чат в SQLite.
В канале необходимо право публикации сообщений. Поддерживаются также публичные группы и каналы. Состав получателей настраивает
администратор; интерфейс пациента не показывает названия и количество чатов.
Снятие прав администратора отключает получателя; права проверяются перед каждой доставкой.

Bot API не предоставляет общий список всех старых чатов бота. Если бот был назначен
администратором до запуска, отправьте **`/register`** в каждом таком чате либо снимите
и верните права администратора при работающем боте. В канале можно опубликовать
`/register` и затем удалить этот пост. Обычное новое сообщение также позволяет
обнаружить ранее неизвестный чат. Регистрация требует настоящих прав бота;
текст сообщения не может подделать статус администратора.

Для каждого обращения сохраняется список получателей, определённый перед подтверждением.
Чаты, добавленные позже, начнут получать новые заявки; архив им не рассылается.
Если получателей нет, бот не принимает подтверждение отправки и предлагает телефон клиники.
Доставка и повторные попытки учитываются отдельно для каждого чата, поэтому сбой
в одном чате не вызывает повтор уже доставленного сообщения в другом.
`/delete` отменяет оставшиеся неотправленные копии; уже доставленные не удаляются.

Утилита `group_id.py` остаётся для необязательного ручного определения ID чата и темы.
Если настроен webhook от старого сервиса, запуск остановится: бот не удаляет его автоматически.

## Ubuntu: отдельная служба

Скопировать **эту папку** в `/opt/uniclinic/TelegramBot`. Команды от root:

```bash
apt-get update
apt-get install -y python3 python3-venv
id uniclinic-bot >/dev/null 2>&1 || useradd --system --user-group --home-dir /var/lib/uniclinic-bot --shell /usr/sbin/nologin uniclinic-bot
cd /opt/uniclinic/TelegramBot
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
cp -n .env.example .env
nano .env
chown root:uniclinic-bot .env
chmod 640 .env
cp uniclinic-bot.service /etc/systemd/system/uniclinic-bot.service
systemctl daemon-reload
systemctl enable --now uniclinic-bot
systemctl status uniclinic-bot --no-pager
```

Входящие порты, домен и сертификат боту не нужны: используется long polling.
Нужен исходящий HTTPS к Telegram и OpenAI. Не запускать две копии с одним токеном.
Обновление кода или инструкций: `systemctl restart uniclinic-bot`.
Логи: `journalctl -u uniclinic-bot -n 50 --no-pager`. В логах нет текста заявок и ключей.

## Хранение и доставка

Незавершённая анкета живёт 24 часа. После завершения доставки всем согласованным получателям текст очищается из локальной
очереди; квитанции и ожидающие заявки удаляются через `BOT_RETENTION_DAYS`
(по умолчанию 7 дней). Сообщения в чатах хранятся по правилам этих чатов.
`/delete` удаляет незавершённую анкету и неотправленные заявки, но не сообщения в группе.
При недоступности Telegram очередь повторяет доставку с паузами. При редком обрыве
между доставкой Telegram и записью квитанции возможен повтор с **тем же кодом заявки**;
сотрудники могут отличить такой повтор. Это не подтверждение записи на приём.

OpenAI получает только свободное описание обращения, без отдельно собранных имени
и телефона. Контакты внутри описания маскируются; автоматическое удаление всех
идентифицирующих сведений из произвольного текста не гарантируется. До ввода бот
объясняет передачу и предлагает режим `/operator` без OpenAI. Запрос `store: false`
отключает хранение объекта Response, но не означает гарантированный Zero Data Retention.

## Проверка без токенов и реальных сообщений

```bash
.venv/bin/python -m unittest -v test_bot.py
```

Тесты используют временную базу и поддельные ответы API. Боевые Telegram/OpenAI
подключения нужно проверить отдельно после заполнения ключей и группы.

Документация API:
- https://core.telegram.org/bots/api
- https://developers.openai.com/api/docs/guides/migrate-to-responses
- https://developers.openai.com/api/docs/guides/your-data

## Диалог администратора (21 октября 2026)

После согласия бот отвечает на обычные сообщения; `/ask` больше не обязателен.
«Записаться» начинает сбор ФИО, пожеланий по врачу/времени/формату и телефона.
«Перезвоните мне» спрашивает только имя и телефон. Перед отправкой остаются
просмотр заявки и подтверждение. Бот не подтверждает свободные
слоты: время приёма согласует сотрудник. Вопрос со знаком `?` во время заполнения
анкеты получает ответ, не заменяя ожидаемое поле.

`instructions.txt` задаёт стиль и ограничения, `knowledge.txt` содержит сведения
из предоставленного владельцем документа `инфо_для_бота.docx`. Обновляйте оба
файла вместе. Цены не являются полной сметой лечения; спорные варианты уточняет
клиника. Часы работы 08–17 сохранены, консультации 08–18 из документа обозначены
отдельно как приём по записи. Непроверенные номера старых маршрутов не рекомендуются.
Хранятся последние три пары реплик для контекста, отдельно собранные поля заявки
не добавляются в запрос модели. Контакты в вопросах маскируются; свободный текст
всё равно не следует считать полностью обезличенным.

Уведомления о заявках с сайта отправляет backend сайта в явно настроенную группу.
Они содержат код и ссылку на защищённую админку. Это отдельная очередь от личных
обращений Telegram; для неё не требуется второй polling-процесс бота.
